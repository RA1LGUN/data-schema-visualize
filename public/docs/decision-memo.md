# Schema Atlas：面向团队评审的决策摘要

这是 post-training 数据模型 v3 的设计论证。网站案例为人工构造，不能作为真实模型、环境或生产吞吐的实验结果。

## 建议作出的决策

采用“四类对象 + 强类型 profile”的试点模型：Asset 保存内容，Activity 保存处理过程，Assessment 保存判断，Collection 保存固定版本的集合。先验证真实数据往返和审计查询，再扩大覆盖。

## 五分钟从上往下讲解

1. **问题（30 秒）**：同一道题会被修订，多人可能有不同意见，同一轨迹会被重评分。若只保留最终宽表，就很难解释旧结果。
2. **模型（60 秒）**：答案是内容；写答案是过程；认为答案正确是判断；把该版本选入评测集是集合关系。四者通过精确版本引用相连。
3. **结构（60 秒）**：题干、答案、解析默认保持一棵内容树；通过字段路径定位来源与责任，只有可复用环境、模型和评测器才独立引用。必选规则分共同规则与场景 profile。
4. **案例（90 秒）**：看一次合成材料任务如何经过三人构造、冲突审核、修改、冻结发布、故障运行、评测器修复与重评分。最后阻止 eval-only 内容导入训练，使用另一个独立任务导出 SFT/DPO。
5. **决策（60 秒）**：采用的理由是复用稳定机制与保留审计能力；代价是版本、引用索引、profile 和采用策略的维护。提出可证伪的小规模验收。

## 三种方案的取舍

| 方案 | 优势 | 代价 | 合适的位置 |
|---|---|---|---|
| 单条宽表 | 容易消费 | 多轮审核和多次执行需额外机制 | 导出视图 |
| 每部分独立实体 | 粒度精细 | 概念和联表增多 | 确实独立复用的资源 |
| 内容树 + 通用过程 | 内容可读，历史清晰，跨场景复用 | 必须维护类型契约、引用与采用规则 | 推荐核心模型 |

## 复杂案例证明到哪一层

案例覆盖多模态来源、字段责任、两轮冲突审核、裁决、任务 v1/v2/v3、固定环境、隐藏测试、失败重试、多个候选、verifier 修复后重评分、冻结发布、训练隔离与 SFT/DPO 派生。

这支持“这些语义可以落入同一组对象与关系”的设计覆盖结论。它没有证明真实数据完整导入、大规模查询性能、标注正确率、环境可重放、政策合规或生产系统可靠性。

## 八条必须保留的约束

1. 所有内容引用固定版本，历史不覆盖。
2. produced_by 说明当前快照的生成/导入活动；导入者不冒充原作者。
3. 多来源或多人分工必须有字段责任映射。
4. 所有判断固定 subjects 与 criterion，保留分歧。
5. 运行完成、内容正确、发布资格、训练权限互相独立。
6. unknown、not_collected、withheld、not_applicable 不混为一谈。
7. Collection 固定成员，train/test 属于成员关系。
8. 导出验证用途、来源隔离、奖励与轨迹对齐，而非只改字段名。

## 试点验收

建议选取 30 道 QA、10 个终端任务、20 对偏好样本；这些数量是建议的试点规模，不是已有验证结果。

- 原始格式 → canonical → 目标导出，逐项核对重要内容、引用和未知信息，不允许静默丢弃。
- 抽取一个改答案、一个冲突审核、一个重评分案例，完整追溯其输入、主体、方法、证据与发布版本。
- 对被标记 eval-only 的样本及其派生结果尝试训练导出，必须明确拦截或进入裁决流程。
- 测量导入耗时、存储放大、查询延迟与人工解释成本；在试点开始前由团队定义可接受阈值。
- 让未参与建模的研究员独立回答“谁改了答案、哪次评测器、哪个发布采用了它”。

## 团队常见质疑

**只有四种对象是否只是改名？** 四个主干是职责边界，模型/环境/轨迹仍有不同 payload。减少的是重复的版本和工作流机制，并未抹掉领域类型。

**它能保证答案正确吗？** 不能。它能保留是谁依据什么认为正确，以及后来如何修正。真实性仍由标注与验证方法决定。

**必须建设图数据库和完整事件溯源吗？** 不必须。关系数据库的对象表、引用索引与不可变快照足以启动；大文件放对象存储，消费视图可用 Parquet。

**会不会过度工程化？** 简单 QA 保持一份内容树；仅在存在独立审核、运行或复用需求时增加对应记录。若某团队只需一次性 prompt/completion，直接导出宽表也合理。

**什么时候应拒绝这个方案？** 若真实导入必须频繁绕过类型、常用查询成本超过阈值，或者使用者无法区分内容和判断，就应调整 profile 或结构，而不是继续添加任意 metadata。

## 部署与服务边界

网站是静态交互说明和合成数据浏览器，没有在线编辑、权限引擎、真实模型调用或训练任务执行。Railway 运行的是静态 HTTP 服务。实际数据平台需要进一步实现 profile 校验器、引用校验、权限规则、审核采用策略和 adapters。
