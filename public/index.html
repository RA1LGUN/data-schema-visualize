THE DESIGN QUESTION

当答案变了、审核冲突了、评测器修复了，你还能解释过去的结果吗？

↘
01 / MENTAL MODEL

四个问题。
四种对象。

先把语义分清楚。每一种对象只回答一个问题，
再通过精确的版本引用连接起来。

内容 Asset经由 →过程 Activity产生 →内容或判断 Asset / Assessment选入 →集合 Collection

内部用树组织，跨对象用引用连接。同一轨迹可以被多次评分，同一环境可以被多个任务复用。

02 / STRUCTURE

一棵清楚的树，
一套明确的约束。

点击字段查看含义、类型和必选条件。
共同规则保持稳定，具体场景通过 profile 收紧。

SAME CORE, DIFFERENT PROFILES

简单的题，不承担多余的字段。

不是每条数据都要有环境、标准答案和轨迹。
profile 定义“在这个场景下，还需要什么”。

BENCHMARKS ENTER THROUGH PROFILES

同一个主干，保留不同任务的细节。

下表是适配设计，尚未实现真实数据导入。原格式保留，统一模型提供共同的版本、来源和判断语义。

01 / HLE

多模态专家题

question / image → input；answer / rationale → references；学科、answer_type 与 canary 进入明确的 profile 字段。公开作者署名作为来源事实保留。

公开列无法恢复逐题审核员与审核时间；导入活动不冒充原始构造史。

02 / TERMINAL-BENCH

可执行终端任务

instruction → input；solution → references；environment → Environment；tests → Evaluator；一次 attempt → rollout Activity。

环境、依赖、评测器与运行参数分别固定版本，执行日志形成独立产物。

Harbor 任务格式 ↗
03 / TERMINAL-BENCH-SCIENCE

科学工作流与专家审核

复用终端任务 profile；科学输入与交付物保留其文件格式，领域审核和技术审核分别记录活动与判断。

多轮修订、固定发布和重评分，通过既有关系表达；下方案例展示这种复杂度。

04 / AA BENCH · ALE

先确认数据粒度

有逐题数据：接入相应 task profile。有交互环境：接入 environment / rollout。只有外部总分：保存报告与“来源报告值”判断。

这两个缩写的准确项目和版本仍待确认。成员未知时，不创建声称完整的集合。

明确支持边界，避免同名误配。

    05 / THE DECISION
    值得采用，
    也值得被检验。
    四个主干减少重复机制。是否适合你的团队，
    最终由真实数据、查询成本与导出一致性决定。
    
      
    三个数据模型方案的能力与代价比较
    决策维度A / 单条宽表B / 全部实体化C / 内容树 + 过程记录推荐方案
    
        
    简单 QA 的阅读成本低，一行可读高，需要组合多个对象低，题目内容保持内嵌
    
        
    多轮审核与冲突加列或另存嵌套历史可表达，但类型繁多复用 Activity + Assessment
    
        
    历史重评分容易覆盖旧分数独立评分实体同一输出，多条版本化判断
    
        
    新增任务类型扩展列、空值增加新增实体与关联扩展内容 profile 和方法
    
        
    主要代价历史与关系需要补机制实体维护、联表与学习成本维护 profile、引用和采用规则
    
      
    
      
    以上为架构取舍，不是吞吐、成本或准确率的实测排名。宽表仍然适合作为消费端导出格式。
    
      
    THE CASE FOR ADOPTION
    复杂场景复用机制，
    简单场景保持简单。
    不再为“二审、三审、重评分”分别发明新结构。相同的身份、引用、过程和判断机制，可跨题型复用。
    • 默认内容内嵌，避免无谓拆分。
    • 每次判断都绑定明确对象和版本。
    • 训练与评测共享来源，各自拥有发布规则。
    THE HONEST LIMIT
    结构能容纳证据，
    质量仍需验证。
    有 hash 不代表来源可信；有人审核不代表答案正确；固定镜像不代表外部服务可复现。
    • 缺失的历史无法由 schema 恢复。
    • 隐私、权限与冻结规则需要服务端落实。
    • 大规模查询、真实适配器仍需实测。
    
      
    A FALSIFIABLE PILOT
    用一个小试点，换一个可靠决策。
    建议先接入 30 道 QA、10 个终端任务和 20 对偏好样本。数量仅为试点建议。
    1. 往返不丢信息原格式 → 统一模型 → 目标导出，核对字段与引用。
    2. 历史能解释选一条修订链，还原参与人、证据和发布版本。
    3. 代价能接受实际测量导入耗时、存储放大和审计查询延迟，再决定扩大。
